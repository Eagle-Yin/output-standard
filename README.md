# output-standard · 让 AI 的正式回复有底线的判据库

一套**纯 Python、零依赖**的回复质量判据。它不生成内容，只回答一个问题：**这段回复够不够格发给一个很忙、很懂行、不想读废话的人。**

## 它拦什么

| 判据组 | 拦住的具体毛病 | 例子 |
|---|---|---|
| 证据 | 说「已完成」却拿不出本轮痕迹 | 「迁移已全部完成。」← 无退出码、无文件、无回读 |
| 数字 | 报出的数字既无出处也不会复算 | 「命中 47 条」← 47 从哪来的 |
| 措辞 | 把判断推回给用户、未验证措辞、边界节复活 | 「下一步要不要我…」「应该可以」 |
| 交付 | 指路式交付、占位符、过程播报进正文 | 「详见第 3 节」「定稿 hits[]…」 |
| 可读性 | 拿脚本路径和函数名当解释 | 「`kw_ok()` 返回 `False`」← 那又怎样 |
| 形状 | 结论不在最前、缺要点节、注脚不全 | —— |
| 版式 | 无横幅、注脚混机器串、要点是一堵墙、段落过长 | 「`hits []` `exit=0` `3558 字符`」 |

## 60 秒上手

```bash
git clone <this-repo> && cd output-standard
python tests/smoke.py            # 判据自检
python tests/test_looks.py       # 版式判据 9 例
python tests/test_reply_hits.py  # 全量回归 71 例
python tests/test_portable.py    # 脱离环境也能跑
```

当判据用：

```python
import sys; sys.path.insert(0, "judge")
import reply_rules

hits = reply_rules.review(draft)   # [] 就是可以发
for h in hits:
    print(h)                       # 每条都是给人看的整改指引
```

## 三条设计取舍

**一、短回复豁免。** 400 字以下的回复不查版式。逼人给一句「改好了」配横幅和注脚，只会让所有人把闸关掉。

**二、判据只判结构，不判内容对不对。** 它能发现「说了完成却没有证据」，发现不了「证据是真的但结论错了」。后者只能靠功能测试。所以它是一道筛子，不是替代品。

**三、不合规就给人话。** 每条命中都是「哪里错＋怎么改」的中文句子，不是错误码。整改的人不需要读源码。

## 边界

- 只处理纯文本，不认渲染结果。表格在 Markdown 里算表格，在纯文本里就是一行竖线——所以横幅用引用块而不是图片。
- 中文为主。英文长句的段落阈值没有实测数据支撑。
- 判据本身也需要回归：改一条正则就可能误伤历史用例，请每次都跑 `test_reply_hits.py`。

## 出处

这套判据是从一个真实在用的个人智能体里抽出来的，跑在 Windows + Hermes 上，服务一个做企业流程咨询的人。抽出来的部分不含任何个人路径、密钥或私有配置。
